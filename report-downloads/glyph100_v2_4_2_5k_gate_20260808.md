# Glyph-100M v2.4.2 5k quality gate

## Decision

**PASS for one controlled continuation from 5k to 10k.** This was a stability and early-learning decision, not a claim that the model was already useful.

## Evidence before launch

- Checkpoint: `checkpoints/glyph-100m-v2_4_2-5k/step_0005000.pt`
- Checkpoint SHA256: `aad89bc2827a4d626092f8da827ecc549afe6c414e837c94b7543ac9ffafc09a`
- Variant: `glyph-100m`
- Dataset: `glyph100_dataset_v2_4_2_core`
- Step: `5000`
- Context length: `512`
- Tokenizer SHA256: `21bad2b08f1081afee40fbb6d5489d8199deebd7b81d76a34b347f2f01dd4029`
- Batch / accumulation: `4 / 8`
- Effective tokens per optimizer step: `16,384`
- Optimizer, scheduler and sampler state: present

Validation loss fell monotonically from `7.3346` at step 500 to `4.5994` at step 5000. All seven fixed source-specific validation sets improved between 1k and 5k.

## Matched generation gate

The same 20 base-LM prompts, two decoding presets and deterministic seeds were used for v2.4.1 and v2.4.2.

| metric | v2.4.1 5k | v2.4.2 5k |
|---|---:|---:|
| heuristic average | 3.000 | 3.175 |
| repetition samples | 13/40 | 13/40 |
| pseudo-ency samples | 7/40 | 0/40 |
| web residue samples | 0/40 | 0/40 |

Pairwise result: v2.4.2 won 14, v2.4.1 won 9, with 17 ties.

The heuristic happened to score v2.4.2 3k slightly above 5k. Manual review did not treat this small-panel difference as a stop signal because validation loss was still falling, source losses were improving and v2.4.2 had removed the obvious pseudo-ency signal seen in v2.4.1.

## Safety gate

The continuation was allowed only after a 100-step P100 smoke test passed with finite loss, finite model parameters, successful evaluation, checkpoint save/reload and no OOM or crash.
